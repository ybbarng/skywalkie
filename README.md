# Skywalkie

**비행기에서 떨어져 앉은 두 사람이 인터넷 없이 대화하는 앱**

기내 Wi-Fi를 사거나 승무원을 부르지 않고, 두 사람의 휴대폰만으로 둘만의 통신망을 만든다.
메시지를 주고받고, 음악을 들으면서 목소리로 이야기하고, 얼굴을 본다.

```
     안드로이드 폰                      아이폰
   ┌──────────────┐                ┌──────────────┐
   │   핫스팟 열기 │◀── Wi-Fi ─────│  목록에서 선택│
   │              │                │              │
   │  💬 메시지    │◀──── TCP ─────▶│  💬 메시지    │
   │  🎙 목소리    │◀── WebRTC ────▶│  🎙 목소리    │
   │  📹 얼굴      │◀── WebRTC ────▶│  📹 얼굴      │
   └──────────────┘                └──────────────┘
          │                                │
          └───── 인터넷 없음. 서버 없음. ────┘
```

## 무엇이 되나

| | |
|---|---|
| 💬 **메시지** | 주고받고 기기에 저장된다. 비행기에서 내린 뒤에도 다시 본다 |
| 🎙 **목소리** | **음악을 끄지 않고** 대화한다. 누르고 말하기와 항상 열기 둘 다 |
| 📹 **얼굴** | 영상 통화. 통신 상태에 맞춰 화질이 알아서 바뀐다 |
| 🔵 **블루투스** | 핫스팟이 막혀도 글로는 대화한다 |
| 📦 **보관** | 대화를 꺼내 두었다가 언제든 되돌린다 |
| 🎨 **캐릭터** | 상대의 캐릭터가 말할 때 입을 움직인다 |
| 🌗 **밝기** | 밝은 화면과 어두운 화면 |

## 왜 이렇게 만들었나

**기내 Wi-Fi로는 두 폰이 서로 통신할 수 없다.** 대부분의 기내 AP가 단말끼리의 통신을 막기 때문이다. Wi-Fi Direct는 아이폰이 지원하지 않고, 블루투스 클래식은 애플 인증 부품에만 열려 있다.

살아남은 방법은 두 가지였다.

1. **안드로이드가 핫스팟을 열고 아이폰이 붙는다** — 셀룰러 없이도 사설 Wi-Fi가 만들어진다. 음성과 영상까지 감당한다
2. **블루투스 저전력(BLE)** — 초당 수 KB라 글자만 나른다

그래서 1번을 주 경로로, 2번을 보조로 쓴다. 자세한 검토는 [기술 선택과 근거](./docs/02-tech-decisions.md)에 있다.

## 설치

### 안드로이드

[릴리스](../../releases)에서 `.apk`를 내려받아 누른다. "출처를 알 수 없는 앱" 설치를 한 번 허용해야 한다.

### 아이폰

유료 개발자 계정이 없어서 **USB로 설치하고 7일마다 다시 깔아야 한다.**

```
1. 아이폰을 맥에 USB로 연결
2. 아이폰에서 "이 컴퓨터를 신뢰"
3. pnpm build:ios:device
4. 아이폰 → 설정 → 일반 → VPN 및 기기 관리 → 개발자 앱 → 신뢰
```

4번을 빠뜨리면 앱이 안 열린다. 처음 한 번만 하면 된다.

**앱은 7일 뒤 열리지 않는다.** 만료 3일 전부터 앱이 먼저 알리고 대화를 꺼내라고 권한다. 같은 서명으로 덮어쓰면 대화가 남는다.

자세한 절차는 [빌드와 배포](./docs/08-build-release.md)에 있다.

## 여행 전 점검표

```
D-7   두 폰에 앱을 깔고 집에서 연결해본다
D-3   비행기 모드에서만 연결되는지 확인한다    ← 가장 중요
D-1   아이폰에 앱을 다시 설치한다 (7일 시계 되감기)
D-1   두 폰 완충 + 보조 배터리
당일   탑승 전에 한 번 더 연결해본다
```

**D-3의 비행기 모드 시험을 빠뜨리지 않는다.** 집에서 잘 되던 것이 비행기 모드에서 안 되는 경우가 있고, 이때 발견하면 고칠 시간이 있다.

## 아이폰이 없어도 시험하기

아이폰은 여자친구 폰이라 늘 손에 있지 않다. 그래서 **맥을 상대 폰처럼 쓰는 도구**를 만들어 두었다.

```bash
pnpm peer --host              맥이 받는 쪽. 폰이 붙어 온다
pnpm peer --guest --to <주소>  맥이 거는 쪽. 폰이 핫스팟을 켠 경우
```

앱과 **똑같은 코드**로 말한다. 터미널에 친 글이 폰으로 가고, 폰에서 온 글이 터미널에 뜬다. 여기서 대화가 되면 규약이 맞다는 뜻이다.

자세한 것과 "이걸로도 확인 안 되는 것"은 [테스트](./docs/09-testing.md) 5-1장에 있다.

## 개발

```bash
pnpm install
pnpm expo prebuild        # 네이티브 프로젝트 만들기

pnpm dev:android          # 안드로이드에 개발용 앱 설치
pnpm dev:ios              # 아이폰에 개발용 앱 설치
pnpm start                # 이미 설치했다면 이것만

pnpm verify               # 검사 + 타입 + 테스트 + 층 규칙
```

WebRTC와 블루투스가 들어가서 **Expo Go로는 못 돌린다.** 개발용 앱을 한 번 만들어 설치하고 그 위에서 개발한다.

필요한 것: Node 20+, pnpm 10+, **JDK 17**, Xcode 16+, Android SDK 35+

## 코드 구조

```
src/
├── domain/          뜻. 메시지란 무엇인가. 아무것도 import 하지 않는다
├── application/     할 일. "메시지를 보낸다"는 절차와 바깥에 요구하는 약속
├── infrastructure/  방법. 소켓, 블루투스, 데이터베이스, WebRTC
├── presentation/    화면
└── composition/     조립. 어떤 구현을 끼울지 정하는 유일한 곳
```

의존 방향은 안쪽을 향한다. `domain`은 React도 SQLite도 소켓도 모른다.

**이렇게 나눈 이유**는 연결 방식이 세 갈래이고 비행 중에 바뀌기 때문이다. "메시지를 보낸다"는 뜻은 셋 모두에서 같고 달라지는 건 방법뿐이라, 뜻을 안쪽에 두고 방법을 갈아 끼울 수 있게 했다.

자세한 것은 [코드 구조](./docs/03-architecture.md)에 있다.

## 만드는 순서

[작업 카드](./docs/tasks/README.md)에 25개로 쪼개 두었다. 중간에 멈춰도 쓸 수 있는 지점이 있다.

| 지점 | 무엇이 되나 |
|---|---|
| **T14까지** | **글로 대화한다.** 목적의 절반은 달성된다 |
| **T17까지** | **음악 들으며 목소리로 대화한다.** 원래 하려던 것이 전부 |
| T19까지 | 대화가 앱보다 오래 산다. 아이폰 7일 문제 해결 |
| T21까지 | 핫스팟이 막혀도 대화한다 |
| T24까지 | 사진, 이모티콘, 심심풀이 |

## 개인정보

모든 데이터가 두 기기 밖으로 나가지 않는다. 계정도 서버도 없고, 사용 기록을 수집하는 코드가 들어 있지 않다.
