# T07 — 통신 규약: 봉투와 바이트 자르기

**단계** 연결 · **상태** 대기 · **먼저** T03, T04

## 목표

두 기기가 주고받을 말의 형식을 정하고, 바이트 흐름을 메시지로 올바로 자른다. **연결 방식과 무관한 순수한 코드**라 전부 컴퓨터에서 시험할 수 있다.

src/infrastructure/transport/protocol/

### 봉투

[04-transport-spec.md](../04-transport-spec.md) 3장의 형식 그대로. `zod`로 정의하고 **받을 때마다 검사한다.**

**모르는 종류가 와도 연결을 끊지 않는다.** 조용히 무시하고 기록만 남긴다. 상대가 다른 버전의 앱일 수 있기 때문이다. 이 규칙이 없으면 한쪽만 업데이트했을 때 대화가 통째로 안 된다.

### 바이트 자르기

```
┌──────────────────┬──────────────────────────────┐
│ 길이 4바이트      │ 내용 (JSON, UTF-8)           │
└──────────────────┴──────────────────────────────┘
```

TCP는 흐르는 물이라 한 번 보낸 것이 여러 번에 나뉘어 오거나, 여러 번 보낸 것이 한 번에 붙어 온다. `FrameDecoder`가 이걸 전부 올바로 나눠야 한다.

**반드시 막아야 할 것**: 길이 값이 1 MB를 넘는다고 주장하면 연결을 끊는다. 안 그러면 이상한 값 하나로 메모리를 통째로 잡아먹는다.

길이가 0이면 살아있는지 확인하는 신호다.

### 순번 다루기

```ts
class SeqTracker {
  observe(seq: number): 'new' | 'duplicate' | 'gap'
  missing(): number[]
}
```

길을 갈아탈 때 같은 메시지가 두 번 올 수 있으므로 겹침 판단이 꼭 필요하다.

## 테스트

**이 카드의 테스트가 이 앱에서 가장 값지다.** 두 기기 사이가 가장 위험한 곳이기 때문이다.

바이트 자르기:
- 한 번에 딱 맞게 온 경우
- 반씩 잘려서 두 번에 온 경우
- 한 바이트씩 온 경우
- 세 메시지가 한 번에 붙어 온 경우
- 길이 헤더가 잘려서 온 경우
- 1 MB를 넘는다고 주장하는 경우 → 연결을 끊는다
- 길이 0 → 하트비트로 인식

봉투:
- 모르는 종류가 와도 연결이 유지된다
- 필수 항목이 빠지면 거절된다
- JSON이 망가졌으면 앱이 죽지 않는다

**무작위 바이트 시험**: 아무 바이트나 수천 번 던져도 앱이 죽지 않는지 확인한다. 씨앗을 고정해 실패하면 재현할 수 있게 한다.

순번:
- 빠짐, 겹침, 뒤바뀜을 각각 올바로 판단한다
- 숫자가 아주 커져도 맞다
