# 가상 기기 두 대

폰이 없어도 **진짜 앱 코드를 그대로 돌려본다.** 핫스팟을 켜고, 서로
찾고, 붙고, 인사하고, 말을 주고받는 것까지 브라우저 안에서 다 된다.

```bash
pnpm demo          # 묶고 http://127.0.0.1:8777 로 띄운다
pnpm demo:build    # 묶기만 한다
```

## 무엇이 진짜인가

`src/` 의 도메인·응용·통신 규약은 순수 TypeScript 라 React Native
없이도 돈다. esbuild 가 그걸 그대로 묶어 가상 기기 두 대에 얹었다.

| 진짜로 도는 것 | 어디 것인가 |
|---|---|
| 보내기·받기·재전송 | `src/application/messaging/` |
| 놓친 말 되찾기 | `ConversationSync` |
| 읽음·전달 표시 | `MarkAsRead`, `ack`/`read` 봉투 |
| 봉투 만들고 읽기 | `encodeEnvelope` / `FrameDecoder` |
| 화면 단계 판단 | `decidePhase` |
| 안내 문구 | `copyFor` |
| 색·캐릭터 | `theme/colors.ts`, `characters/` 와 같은 값 |

로그 창에 뜨는 바이트 수는 **실제로 만들어진 봉투 크기**다. 지어낸
숫자가 아니다.

## 흉내 내는 것 셋

- **선** — 진짜 Wi-Fi 대신 브라우저 안(`demo/src/network.ts`)에서
  바이트를 나른다. 느리게 하거나, 잃어버리게 하거나, 토막 내서
  보낼 수 있다
- **저장소** — SQLite 대신 메모리(`demo/src/MemoryRepository.ts`).
  `ConversationRepository` 를 그대로 구현한다
- **화면** — React Native 대신 HTML

이 셋 말고는 앱과 같은 코드가 돈다.

## 해보기

`핫스팟 켜기 → Wi-Fi 에 들어가기` 를 차례로 누른다. 한 번에 하려면
**바로 이어주기**.

**서로 찾아 붙는 버튼은 없다.** 앱에 그런 버튼이 없기 때문이다.
켜져 있는 동안 붙는 쪽이 알아서 계속 찾고, 조건이 갖춰지는 순간
저절로 이어진다. 사람이 누르는 것은 핫스팟과 Wi-Fi 뿐이다.

붙고 나면 아무 쪽에나 글을 쓴다. 칠 때마다 `typing` 이 건너가고,
보내면 `message → ack → read` 가 차례로 오간다.

- **끊겼다 되찾기 해보기** — 멀어지고, 양쪽이 각자 글을 쓰고, 돌아온다.
  놓친 말이 `sync_response` 로 건너와 양쪽 순서가 같아지는 걸 본다
- **멀어지기 / 돌아오기** — 위를 손으로 해본다. 돌아오면 저절로 붙는다
- **핫스팟 끄기** — 여는 쪽과 붙는 쪽에 각각 다른 안내가 뜬다
- **바이트 쪼개기** — 봉투를 반씩 잘라 보낸다. `FrameDecoder` 가
  이어 붙이는지 본다
- **10% 잃어버리기 / 느린 땅** — 좁고 나쁜 길에서도 되는지 본다
- **밝은 화면** — 두 벌의 색을 바꿔 본다

## 폰 두 대가 달라 보이는 것

같은 앱이지만 **같아 보이지 않는다.** 왼쪽은 안드로이드답게, 오른쪽은
아이폰답게 그린다. 모서리, 위쪽 구멍, 아래 막대, 말풍선 모서리,
입력줄, 글꼴, 이름을 가운데 두느냐 왼쪽에 붙이느냐가 갈린다.

실제로 두 기기에서 앱이 어떻게 달라 보이는지 알아야 해서 흉내 냈다.
이건 데모의 껍데기일 뿐이고, 앱은 React Native 가 알아서 한다.

## 폰 밖에 있는 것

가운데 창은 앱에 없다. 가상 망에서 실제로 오간 봉투와, 진짜
`decidePhase` 가 고른 단계(`need-hotspot` 같은)를 적어둔다.
**폰 화면 안에는 그런 영어가 뜨지 않는다.**

## 여기 없는 것

통화·사진·낙서는 카메라와 마이크가 있어야 해서 뺐다. 그건
`pnpm test` 가 확인한다.

`biome` 검사에서는 뺐다. 앱에 들어가는 코드가 아니라 브라우저에서만
도는 껍데기라 규칙이 다르다. `demo/app.js` 는 묶은 결과물이다.
